## Introduction

Acquisition special-access-programmes, or Acquisition SAPs, are the compartmented side of weapons development. They are used when a defence technology, platform, sensor, munition, test method, manufacturing source or procurement plan is so sensitive that ordinary Secret or Top Secret handling is judged inadequate. Their purpose is not simply to hide a finished weapon. It is to protect the vulnerable middle of the acquisition chain: research, design trade-offs, test failures, contractor teams, budget lines, production facilities and deployment timelines before an adversary can learn what is being built or how to counter it.

Within the broader world of special-access-programmes, including waived and unacknowledged programmes, Acquisition SAPs are especially important because they connect secrecy to public money and industrial activity. The open record shows both sides of the bargain. Acquisition SAPs can enable revolutionary systems such as stealth aircraft to be developed before they are exposed. They can also narrow oversight, disguise costs in public budget documents and make ordinary [accountability]({{ 'accountability/' | relative_url }}) harder unless [Congress]({{ 'congress/' | relative_url }}), auditors and programme officials retain enough access to see what is happening.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.cdse.edu/Portals/124/Documents/student-guides/SA001-guide.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: cdse.edu">[cdse.edu]</a><span class="citation-popover" role="note"><span class="citation-popover-source">cdse.edu</span><span class="citation-popover-title">Student Guide Course: Special Access Program (SAP</span><span class="citation-popover-snippet">“Black Programs” and were generally restricted to protecting DoD acquisition programs. ## What makes an Acquisition SAP different

An Acquisition SAP is a special-access compartment built around the acquisition lifecycle: research, development, testing, evaluation, modification or procurement. Defence security training describes Acquisition SAPs as the dominant category of Department of Defense SAPs, estimating that roughly 75 to 80 per cent of DoD SAPs are acquisition-related, because they involve buying or building something such as a weapon system or aircraft.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.cdse.edu/Portals/124/Documents/student-guides/SA001-guide.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: cdse.edu">[CDSE]</a><span class="citation-popover" role="note"><span class="citation-popover-source">cdse.edu</span><span class="citation-popover-title">Student Guide Course: Special Access Program (SAP</span><span class="citation-popover-snippet">“Black Programs” and were generally restricted to protecting DoD acquisition programs. The distinction matters because the most sensitive information in a weapons programme is often not a single document marked “Top Secret”. It may be the combination of engineering details, supplier identities, test anomalies, signature measurements, software assumptions, production bottlenecks and schedule signals. An adversary does not need the whole blueprint to gain value. Learning that a low-observable aircraft has a maintenance weakness, that a sensor works in one band but not another, or that a missile programme is behind schedule can shape countermeasures, [intelligence]({{ 'intelligence/' | relative_url }}) collection and military planning.

Public DoD policy now places SAP oversight across several senior offices, including the Under Secretary of Defense for Research and Engineering and the Under Secretary of Defense for Acquisition and Sustainment, and it explicitly assigns the Director of [Operational Test]({{ 'operational-test/' | relative_url }}) and Evaluation a role in identifying acquisition SAPs for operational test and evaluation oversight. That is a revealing detail: even in compartmented programmes, acquisition secrecy has to be reconciled with the ordinary defence-acquisition questions of whether the system works, whether it is ready for realistic testing and whether it is worth the cost.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.esd.whs.mil/portals/54/documents/dd/issuances/dodd/520507p.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: esd.whs.mil">[WHS ESD]</a><span class="citation-popover" role="note"><span class="citation-popover-source">esd.whs.mil</span><span class="citation-popover-snippet">Open source on whs.mil.</span></span></span>

## Research and development secrecy

The strongest case for an Acquisition SAP appears early in a programme, when a new military advantage can still be lost cheaply. During research and development, the programme may need to protect scientific assumptions, experimental materials, modelling tools, radar cross-section data, propulsion work, specialised software, manufacturing methods and the identity of small expert teams. In that phase, secrecy is not only about preventing public embarrassment or preserving surprise; it is about denying foreign intelligence services enough fragments to copy, sabotage or design around the technology.

The F-117 [stealth]({{ 'stealth/' | relative_url }}) fighter is the classic public example. DoD training material uses the F-117 and Lockheed’s Skunk Works as examples of the “black programmes” era, when SAPs largely protected acquisition programmes. The later GAO review of special access acquisition programmes also identified the F-117A as a case where special access protection covered an entire programme throughout development and acquisition.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.cdse.edu/Portals/124/Documents/student-guides/SA001-guide.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: cdse.edu">[CDSE]</a><span class="citation-popover" role="note"><span class="citation-popover-source">cdse.edu</span><span class="citation-popover-title">Student Guide Course: Special Access Program (SAP</span><span class="citation-popover-snippet">“Black Programs” and were generally restricted to protecting DoD acquisition programs. They were “Black...Read more...</span></span></span>

What made the F-117 distinctive was not secrecy alone. RAND’s later analysis found that the programme used a small, hand-picked Air Force management staff, goal-like specifications rather than rigid requirements, and a development contract structure that allowed rapid decisions. RAND’s point was not that SAP status magically made acquisition efficient, but that the programme’s compartmented environment allowed a smaller group with unusual authority to move quickly while developing stealth and a new precision-strike concept under exceptional security demands.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.rand.org/pubs/research_briefs/RB42.html" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: rand.org">[RAND Corporation]</a><span class="citation-popover" role="note"><span class="citation-popover-source">rand.org</span><span class="citation-popover-title">Corporation Acquisition Lessons of the Stealth Fighter &#124; RAND</span><span class="citation-popover-snippet">Corporation Acquisition Lessons of the Stealth Fighter &#124; RAND</span></span></span>

That same feature is also a risk. A small, cleared team can reduce leaks and speed decisions, but it can also reduce challenge, independent review and institutional memory. Acquisition SAPs therefore create a recurring tension: the very controls that protect an emerging weapon may also make it harder for outsiders, and sometimes even adjacent defence officials, to spot technical optimism, duplication or weak cost estimates before the programme grows.

## Testing and procurement controls

Testing is one of the hardest parts of secret weapons development to conceal because it generates physical signatures. Aircraft need ranges. Sensors need targets. Missiles need telemetry. Prototype vehicles need storage, transport, maintenance and safety procedures. The programme may be hidden, but the activity cannot be made weightless.

Acquisition SAP controls therefore tend to compartment not only technical documents but also test ranges, flight schedules, support crews, telemetry channels, after-action reports and even the unclassified descriptions attached to [contracts]({{ 'contracts/' | relative_url }}). The point is to prevent outsiders from correlating scattered clues: an unusual range closure, a contractor team on site, a new hangar modification, a budget movement, a logistics shipment and a test anomaly may together reveal more than any single classified document.

The open record around the B-2 bomber shows why testing and procurement remain sensitive long after a programme is acknowledged. GAO reported in 1994 that unresolved technology problems, including radar and software issues, together with testing delays, could push acquisition costs for 20 B-2 aircraft above a congressional cost ceiling. GAO also noted that most planned flight-test hours had not yet been completed and that test results had already revealed problems still awaiting correction.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://gao.justia.com/department-of-defense/1994/9/b-2-bomber-nsiad" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: gao.justia.com">[gao.justia.com]</a><span class="citation-popover" role="note"><span class="citation-popover-source">gao.justia.com</span><span class="citation-popover-title">GAO Reports</span><span class="citation-popover-snippet">GAO Reports</span></span></span>

A later GAO report in 1997 showed how low-observable systems can keep producing acquisition risk after the basic aircraft exists. The Air Force reported that estimated B-2 acquisition costs had stabilised at about $44.754 billion, but GAO warned that costs could rise if flight testing was extended, if more performance deficiencies appeared, or if unplanned work was needed to maintain low-observable features. GAO also noted that the aircraft had achieved initial operational capability in an interim configuration, while the Air Force was still dealing with difficulties maintaining low-observable characteristics at the main operating base.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.govinfo.gov/content/pkg/GAOREPORTS-NSIAD-97-181/html/GAOREPORTS-NSIAD-97-181.htm" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: govinfo.gov">[GovInfo]</a><span class="citation-popover" role="note"><span class="citation-popover-source">govinfo.gov</span><span class="citation-popover-title">GAOREPORTS NSIAD</span><span class="citation-popover-snippet">GAOREPORTS NSIAD</span></span></span>

Those details illustrate a broader lesson for Acquisition SAPs: secrecy can protect the test regime from foreign collection, but it cannot abolish engineering uncertainty. A secret aircraft still has maintainability problems. A classified munition still faces software defects. A compartmented sensor still needs realistic operational testing. The special-access wrapper changes who can see those problems, not whether the problems exist.

## Contractor access and industrial compartmentalisation

Secret weapons programmes usually cannot be built by government personnel alone. They depend on prime contractors, subcontractors, laboratories, range operators, software teams, manufacturing specialists and facility-security staff. Acquisition SAPs therefore have to manage an awkward reality: the programme must be tightly held, but it must still move through an industrial base.

The contractual hinge is often the DD Form 254, the Department of Defense Contract Security Classification Specification. Current instructions describe it as the principal authorised means for providing security classification guidance and requirements to a contractor under a contract or agreement requiring access to classified information. It is not merely a bureaucratic attachment; it tells the contractor what level of clearance, safeguarding, handling and classification guidance applies to the work.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.esd.whs.mil/portals/54/documents/dd/forms/dd/dd0254-Inst.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: esd.whs.mil">[WHS ESD]</a><span class="citation-popover" role="note"><span class="citation-popover-source">esd.whs.mil</span><span class="citation-popover-snippet">Open source on whs.mil.</span></span></span>

For SAP contracts, the controls go further. The 2025 DoD SAP Security Manual says DD Forms 254 for SAP contracts should, as far as possible, be unclassified or controlled unclassified information, but may be supplemented by a separate classified SAP addendum. That addendum identifies the specific SAP information and programme identifiers tied to the contract, and contractors are not allowed access to SAPs that are not identified on it. Prime contractors must also obtain approval before releasing SAP information to subcontractors, coordinate prospective subcontractor access, and tailor the DD Form 254 to the support being sought.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.esd.whs.mil/Portals/54/Documents/DD/issuances/dodm/520507m1.PDF" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: esd.whs.mil">[WHS ESD]</a><span class="citation-popover" role="note"><span class="citation-popover-source">esd.whs.mil</span><span class="citation-popover-snippet">Open source on whs.mil.</span></span></span>

This is how compartmentation becomes practical rather than theoretical. A subcontractor might be cleared to machine a component without being told the full platform. A software team might work inside a SAP facility but only on one subsystem. A supplier might see performance tolerances but not operational purpose. A contractor security officer may manage personnel access, document control and facility accreditation without every worker learning the programme’s wider mission.

That structure protects secrecy, but it also has costs. It can slow integration, complicate troubleshooting and prevent engineers in different compartments from comparing assumptions. It can make supply-chain resilience harder if only a few approved facilities or individuals can do the work. It can also create uneven visibility between the government programme office, the prime contractor and subcontractors, especially when classified addenda, need-to-know determinations and security approvals become gating items for ordinary acquisition decisions.

## Cost visibility and the black-budget problem

The phrase “black budget” can make Acquisition SAPs sound as though they exist outside public finance. The better reading of the open evidence is more precise: SAP funding may be hidden or disguised in unclassified budget documents, but it is not supposed to be outside the defence budgeting and oversight system.

GAO’s 1992 unclassified summary of a classified review is still one of the clearest public explanations. It found that funding lines for SAPs were deliberately disguised in unclassified budget documents to protect security, but that the sampled programmes followed the same resource justification, execution, review and reprogramming processes as non-SAP defence acquisition programmes. GAO also found no major difference between the cost, schedule and performance problems of sampled special access acquisition programmes and ordinary acquisition programmes; former SAPs such as the F-117A, B-2, Advanced Cruise Missile and others suffered cost growth, schedule slips or performance shortfalls much like non-SAP programmes.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.gao.gov/assets/nsiad-93-78.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: gao.gov">[GAO]</a><span class="citation-popover" role="note"><span class="citation-popover-source">gao.gov</span><span class="citation-popover-snippet">NSIAD-93-78 Defense Acquisition: Oversight of Special Access Programs Has Increased...</span></span></span>

That finding is important because it punctures two opposite [myths]({{ 'myths/' | relative_url }}). The first myth is that an Acquisition SAP is an uncontrolled secret fund. The second is that special access status guarantees elite acquisition performance. In practice, SAPs may use ordinary budget controls behind a classified wall, while still suffering familiar acquisition failures: immature technology, concurrency, optimistic schedules, late testing discoveries, integration problems and underestimated support costs.

Congressional reporting law tries to preserve cost visibility inside the cleared oversight channel. Under 10 U.S.C. §119, the Secretary of Defense must submit annual reports on DoD SAPs to the defence committees, including total requested SAP funding and, for each programme, a brief description, major milestones, actual prior costs, estimated total cost and projected costs. New SAP reports must also include a total programme cost estimate and identify similar existing programmes or technologies.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.law.cornell.edu/uscode/text/10/119" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: law.cornell.edu">[Legal Information Institute]</a><span class="citation-popover" role="note"><span class="citation-popover-source">law.cornell.edu</span><span class="citation-popover-title">Legal Information Institute10 U.S. Code § 119</span><span class="citation-popover-snippet">Special access programs: congressional oversight &#124; U.S. Code &#124; US Law &#124; LII / Legal Information Institute...</span></span></span>

The same law also explains why waived and unacknowledged SAPs are so contentious. The Secretary of Defense may waive inclusion of certain information in the normal reports if disclosure would adversely affect national security, but must provide the information and justification jointly to the chair and ranking minority member of each defence committee. In other words, waiver narrows the reporting channel; it does not erase the statutory premise that secret weapons programmes need congressional oversight.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.law.cornell.edu/uscode/text/10/119" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: law.cornell.edu">[Legal Information Institute]</a><span class="citation-popover" role="note"><span class="citation-popover-source">law.cornell.edu</span><span class="citation-popover-title">Legal Information Institute10 U.S. Code § 119</span><span class="citation-popover-snippet">Special access programs: congressional oversight &#124; U.S. Code &#124; US Law &#124; LII / Legal Information Institute...</span></span></span>

## Why secrecy can help acquisition

The best argument for Acquisition SAPs is that some military technologies lose value if they are exposed too early. A stealth aircraft, electronic-warfare technique, sensor-processing method or advanced munition can be countered more easily once adversaries know what signature to search for, what frequency range to study, what operating concept to expect or what industrial dependency to target.

SAP controls can also create a smaller decision environment. The F-117 case suggests that, under certain conditions, a compact, empowered programme office can make fast trade-offs without the drag of a large conventional acquisition bureaucracy. RAND found that the F-117 programme’s small staff, flexible requirements and decision authority were central to its responsiveness.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.rand.org/pubs/research_briefs/RB42.html" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: rand.org">[RAND Corporation]</a><span class="citation-popover" role="note"><span class="citation-popover-source">rand.org</span><span class="citation-popover-title">Corporation Acquisition Lessons of the Stealth Fighter &#124; RAND</span><span class="citation-popover-snippet">Corporation Acquisition Lessons of the Stealth Fighter &#124; RAND</span></span></span>

That benefit is most plausible when the programme has a sharply bounded mission, a manageable contractor base and a clear reason why early exposure would damage national security. It is less persuasive when SAP status becomes a way to shield a broad, long-running or poorly defined effort from ordinary scrutiny. The more a programme grows into production, sustainment and deployment, the harder it becomes to justify keeping every acquisition detail inside the same narrow compartment.

## Why secrecy can hurt acquisition

The acquisition danger is not only that the public cannot see the programme. It is that too few qualified people may be able to challenge it. GAO’s 1992 review found that DoD had properly established the sampled special access acquisition programmes, but had provided less oversight over them than over similarly sized non-SAP acquisition programmes. It also reported that waivers and exemptions had limited review, documentation and reporting requirements, and that earlier audits had found weak internal controls, poor internal communication and inadequate record-keeping.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.gao.gov/assets/nsiad-93-78.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: gao.gov">[GAO]</a><span class="citation-popover" role="note"><span class="citation-popover-source">gao.gov</span><span class="citation-popover-snippet">NSIAD-93-78 Defense Acquisition: Oversight of Special Access Programs Has Increased...</span></span></span>

These are not abstract governance complaints. They map directly onto weapons-development failure modes:


<div class="content-enhancement content-enhancement--caution" markdown="1">

* **Cost estimates can become fragile** when independent cost analysts lack full access to assumptions, test results or contractor data.
* **Technical risk can be under-challenged** when only a small cleared circle sees failures across subsystems.
* **Duplication can persist** when similar efforts are hidden in separate compartments.
* **Operational testing can be delayed or narrowed** when realistic test conditions would expose sensitive characteristics.
* **Contractor dependence can deepen** when only one industrial team has the clearances, facilities and tacit knowledge to continue the work.

</div>

The B-2 example shows how these problems can survive the transition from black development to acknowledged procurement. GAO’s concern was not that secrecy alone caused the B-2’s cost and testing difficulties, but that advanced, low-observable acquisition carried unresolved technical and support risks that Congress needed to see clearly.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.govinfo.gov/content/pkg/GAOREPORTS-NSIAD-97-181/html/GAOREPORTS-NSIAD-97-181.htm" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: govinfo.gov">[GovInfo]</a><span class="citation-popover" role="note"><span class="citation-popover-source">govinfo.gov</span><span class="citation-popover-title">GAOREPORTS NSIAD</span><span class="citation-popover-snippet">GAOREPORTS NSIAD</span></span></span>

## The oversight trade-off that defines Acquisition SAPs

Acquisition SAPs sit between two real dangers. Too little secrecy can expose a breakthrough before it is militarily useful. Too much secrecy can leave expensive mistakes protected from the people who are supposed to find them.

Modern DoD policy reflects an attempt to manage that trade-off through central SAP governance, assigned oversight authorities, SAP Central Offices, security manuals, contractor rules and test-and-evaluation involvement. The 2024 [DoD SAP policy]({{ 'do-d-policy/' | relative_url }}) describes a governance structure that includes a Special Access Program Oversight Committee chaired by the Deputy Secretary of Defense and senior participants from research, acquisition, policy, intelligence, comptroller, cost assessment, legal, information and military offices.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.esd.whs.mil/portals/54/documents/dd/issuances/dodd/520507p.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: esd.whs.mil">[WHS ESD]</a><span class="citation-popover" role="note"><span class="citation-popover-source">esd.whs.mil</span><span class="citation-popover-snippet">Open source on whs.mil.</span></span></span>

The practical test is not whether a weapons programme is secret. Some should be. The practical test is whether the compartment is narrow enough to protect the genuine secret while still allowing competent acquisition review. A well-run Acquisition SAP should be able to answer, inside authorised channels, the same hard questions asked of any major weapon system: What is the military need? What is the technical risk? What are the milestones? What will it cost? What similar programmes exist? Who has access? What happens if testing fails? What must be declassified, transitioned or closed when the special-access justification expires?

That is why Acquisition SAPs are best understood not as a mysterious category above normal classification, but as a controlled acquisition environment. They keep secret weapons programmes compartmented by limiting people, contracts, facilities, documents, budgets and test information to approved channels. Their legitimacy depends on whether those channels remain strong enough to protect the technology without blinding the government to cost, schedule, performance and accountability.

      if (localeMarketMap[normalized]) {
        exactMarket = localeMarketMap[normalized];
        break;
      }

      if (!languageMarket && localeMarketMap[languageOnly]) languageMarket = localeMarketMap[languageOnly];
    }

  }
  function inferFromLocale() {
    var matches = localeMatches();
    return matches.exact || matches.language || '';
  }
  function inferFromTimezone() {
    var tz = '';
    try { tz = String(Intl.DateTimeFormat().resolvedOptions().timeZone || ''); } catch (err) {}
    if (!tz) return '';
    for (var i = 0; i< timezoneRules.length; i += 1) {
      var rule = timezoneRules[i] || {};
      try {
        if (new RegExp(rule.pattern).test(tz)) return rule.market;
      } catch (err) {}
    }
    return '';
  }
  function inferMarket(available, options) {
    available = Array.isArray(available) ? available : [];
    options = options || {};
    var storageKey = options.storageKey || 'phoenix-affiliate-market';
    try {
      var saved = window.localStorage && localStorage.getItem(storageKey);
      if (saved && available.indexOf(saved) >= 0) return saved;
    } catch (err) {}
    var timezoneMarket = inferFromTimezone();
    if (timezoneMarket && available.indexOf(timezoneMarket) >= 0) return timezoneMarket;
    var localeMarkets = localeMatches();
    if (localeMarkets.exact && available.indexOf(localeMarkets.exact) >= 0) return localeMarkets.exact;
    if (localeMarkets.language && available.indexOf(localeMarkets.language) >= 0) return localeMarkets.language;
    if (options.defaultMarket && available.indexOf(options.defaultMarket) >= 0) return options.defaultMarket;
    return available[0] || '';
  }

    normalize: normalize,
    inferMarket: inferMarket,
    inferFromLocale: inferFromLocale,
    inferFromTimezone: inferFromTimezone
  };
